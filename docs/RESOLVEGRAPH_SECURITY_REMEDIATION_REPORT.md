## 4. Application Security Controls Assessment

Beyond package dependency scanning, RESOLVEGRAPH enforces a layered defense-in-depth posture:

### 4.1 SQL Injection Defense
- **ORM:** Prisma Client 7.10.1 with `@prisma/adapter-better-sqlite3`.
- **Query Parameterization:** 100% of database queries utilize parameterized prepared statements generated by Prisma. Zero raw string interpolation (`$queryRawUnsafe`) exists in user-facing endpoints.
- **Verification:** Tested with SQL injection vectors (`' OR '1'='1`, `'; DROP TABLE Cases; --`) on `/api/cases`, `/api/complaints/suggest-title`, and `/api/evidence`. All vectors treated strictly as literal string values.

### 4.2 Cross-Site Scripting (XSS) & Content Security
- **React Escaping:** All user-supplied input rendered in UI components is escaped automatically via JSX virtual DOM binding.
- **HTML Report Sanitization:** The new printable HTML report generator (`InvestigationReportService.generatePrintableHtmlReport`) strictly escapes all dynamic fields (titles, dispute amounts, evidence hashes, reasoning) through an `escapeHtml()` helper before injection into printable markup.
- **Content-Type Enforcement:** All API endpoints strictly return `application/json; charset=utf-8` or `text/html; charset=utf-8` with explicit no-sniff headers.

### 4.3 Evidence Storage & Path Traversal Defenses
- **Isolated Directory:** Physical evidence files are stored exclusively in `.private/evidence/`, completely decoupled and hidden from Next.js public routes.
- **Path Traversal Shield:** In `src/app/api/evidence/[evidenceId]/download/route.ts`:
  ```typescript
  const resolvedPath = path.resolve(storedPath);
  const allowedRoot = path.resolve(process.env.EVIDENCE_STORAGE_PATH || '.private/evidence');
  if (!resolvedPath.startsWith(allowedRoot)) {
    return NextResponse.json({ error: 'Access denied: invalid evidence path' }, { status: 403 });
  }
  ```
- **Cryptographic Integrity:** Files are identified and indexed by SHA-256 hashes. Any byte tampering in storage triggers an integrity violation upon retrieval.

### 4.4 Financial Safeguards & Double-Spend Prevention
- **Financial Kill Switch:** Global operational kill switch implemented at `/api/admin/kill-switch`. If enabled, all refund and payout execution calls fail closed with `503 Service Unavailable`.
- **Amount & Balance Sanity:** Refunds cannot exceed original payment amounts; duplicate refund requests for the same transaction ID are rejected with idempotent checks.
- **Sandbox Confinement:** In hackathon/demo configurations, mock payment gateways and PayPal sandbox (`https://api-m.sandbox.paypal.com`) prevent any accidental disbursement of real capital.

### 4.5 AI Prompt Injection & Guardrails
- **Input Sanitization:** `ContentSanitizer.sanitize()` strips dangerous markdown exploits, prompt injection delimiters (`### Instruction:`, `Ignore previous instructions`), and control tokens.
- **PII & Secret Redaction:** `DataRedactor.redact()` filters credit card numbers (Luhn check), Indian Aadhaar/PAN numbers, Social Security Numbers, phone numbers, and API tokens prior to payload transmission to external LLM providers.
